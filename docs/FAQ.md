# 排查问题

**先确认 AstrBot 本体能够正常对话，再排查微信通道。** 不要将真实token、登录二维码、聊天记录或完整配置贴到Issue。

| 现象 | 检查方向 |
| --- | --- |
| 插件安装了但没有回复 | 新增并启用消息平台；填写风险确认、令牌、会话名称及核心白名单；安装插件本身不会自动启用通道 |
| `Read README ...` 配置错误 | 先阅读风险说明，再由实际操作者决定是否确认，不要用别人账号未经授权开启 |
| 提示token未配置 | 环境变量应存在于AstrBot服务/容器中；配置的是变量名而不是变量值；指定变量为空不会回退到明文token |
| 无法连接8899 | 容器内127.0.0.1是容器自身；检查双方私有网络及服务名，不要为排查而开放公网 |
| 401/403 | 核对与MimicWX一致的私有token，不要把值打印到日志或命令行参数 |
| 接口返回跳转 | 使用实际HTTP(S) origin；本插件故意不跟随跳转以避免认证信息泄露 |
| 文字有了但识别成SYS | 客户端无障碍信息不足；按未知身份策略降级，不能推断真实身份 |
| 不@追问不回 | 默认未知身份模式只收明确@；group模式可参与群话题但不能区分匿名成员，启用前评估并关闭不兼容的个人记忆 |
| 群聊增强插件不响应 | 核心白名单和增强插件允许群均需配置生成的wxg标识；QQ专属功能不能直接假定微信支持 |
| 重启后一条消息没回 | 默认跳过启动积压；消费接口及进程中断也可能丢消息；并非可靠消息队列 |
| 遗漏/重复明显 | 是否有第二个消费者；微信虚拟消息列表、上游游标和版本是否兼容；看COMPATIBILITY中的可选补丁 |
| 图片报413 | 核对发送的是Base64 JSON，检查后端请求上限；本插件会将支持的图片压至保守上限 |
| GIF变静态图 | 查看transport可选补丁；仅在已核验的MimicWX环境中应用，并用无隐私测试图在接收端确认 |
| 网页图片不能直接发 | 公开版禁止适配器自行抓取HTTP图片；先由可信插件下载到本地或使用内联图片 |
| 返回“图片格式不支持” | 当前只接收本地/内联PNG、JPEG、GIF；语音、文件和其他格式没有默认发送保证 |
| 收到图片却看不懂 | 本接口没有图片原文，文字占位不是图片；更换视觉模型不会补齐缺失的传输数据 |
| 某一个会话不存在 | 检查改名/重名及账号是否已在群中；其他可用会话应继续工作，后台为degraded |
| 回复到了不对的会话 | 立即停用平台，核查同名、改名、窗口/搜索行为；白名单不是可靠原生会话ID校验 |

只读检查工具只访问status/listen。**不要**用循环调用listen/messages来“看是否有消息”，这会取走正式消费者要处理的消息。
